# 校园食堂菜品推荐系统

基于 Spring Boot、Vue 3 和 MySQL 的校园选餐系统，提供学生选餐与管理员资料维护功能。

## 功能

- 学生账号注册、登录、退出；管理员与学生权限由服务端校验。
- 按食堂、窗口、菜品分类、口味和价格区间组合筛选，支持关键词搜索、排序和分页。
- 从当前筛选结果中等概率抽取一道菜品，空结果提示调整条件，多次抽取允许重复。
- 查看菜品所属食堂窗口、价格、图片、平均分及留言；学生可评分并新增或更新本人留言。
- 管理员维护食堂、窗口、菜品，上传 JPG/PNG 图片，修改菜品并确认删除。
- 菜品采用删除标记保留历史关联，有关联记录的食堂和窗口不能直接删除。
- 热量搭配支持输入1～5000千卡目标和可选食材，按每道一份、最多五道不同菜品返回至多三组推荐。
- 单点自由搭配支持按份选择食材，增减份数并实时汇总已选内容、总份数、总价和估算热量。

## 环境

JDK 21、Maven 3.9、Node.js 22.12 及以上、MySQL 8.0。后端框架固定为 Spring Boot 3.3.5，前端固定为 Vue 3.5.24、Vite 7.2.2。

## 构建与启动

在项目根目录执行：

```powershell
.\scripts\build.ps1
.\scripts\start.ps1
```

启动脚本会询问 MySQL 密码，连接本机 MySQL 并创建独立的 `campus_canteen` 数据库。构建后的前端页面打包进后端 JAR，启动后访问 [校园食堂](http://127.0.0.1:8080)。按 `Ctrl+C` 停止服务。

默认数据库账号为 `root`，可通过当前进程的 `DB_USER`、`DB_PASSWORD` 配置。连接其他实例时，先手动建库，再设置 `DB_URL` 并从 `backend` 目录运行 `java -jar target/campus-canteen-1.0.0.jar`；`start.ps1` 用于默认的本机实例。重新构建前先停止正在运行的服务，避免 Windows 占用 JAR 文件。

首次启动自动建立表并导入采集资料；以后启动依据导入记录跳过，不覆盖已维护的数据。数据库初始化脚本为 `database/01-create-database.sql`，表结构位于 `backend/src/main/resources/schema.sql`。

## 账号

首次启动自动创建管理员 `admin`，随机初始密码保存在 `backend/.run/initial-admin-password.txt`。该文件不纳入版本控制，请妥善保存；文件仅在首次创建管理员时生成。也可以在首次启动前通过 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 指定管理员凭据，密码至少8位。已有管理员不会在重启时被覆盖。

学生通过页面右上角“登录 / 注册”创建账号。账号为4～30位字母、数字或下划线，密码8～30位。数据库保存 BCrypt 密码凭据，接口不返回密码。会话闲置30分钟后失效。

## 数据来源与规则

初始资料来自提供的《食堂(1).docx》，包含同乐食堂、同德食堂、幸福食堂、第五食堂、第六食堂，共20个窗口、67条菜品，售价6～18元。名称、所属关系、价格、窗口采集人均消费和评分保留原始数值。初始化资料集中保存在 `backend/src/main/resources/initial-data.json`。

示例扩展由 `FitnessDataLoader` 在同乐食堂的“轻食健身餐”窗口导入8道轻食菜品和6种单点食材，初始化规模合计5个食堂、21个窗口、81条菜品，价格范围0.50～25元。单点使用独立的导入标记及事务，已有数据库重启后补充一次，后续启动依据标记跳过。

| 单点名称 | 每份配料及份量 | 价格/元 | 估算热量/千卡 |
| --- | --- | ---: | ---: |
| 水煮蛋 | 鸡蛋1个，可食部分约50克 | 1.00 | 78 |
| 清蒸西兰花 | 西兰花100克 | 1.50 | 35 |
| 水煮玉米粒 | 玉米粒100克 | 2.00 | 112 |
| 蒸紫薯 | 紫薯100克 | 2.00 | 86 |
| 米饭 | 熟米饭100克 | 0.50 | 130 |
| 水煮鸡胸肉 | 熟鸡胸肉100克 | 3.00 | 165 |

管理员通过菜品表单选择“单点食材”分类，填写每份价格、配料及份量和热量。营养信息须完整填写，修改后重新进入热量搭配页可取得新资料。其他分类的配料和热量可同时留空。

单点份数在页面内通过加减按钮选择0～99的整数，0份表示取消，可清空全部选择。总价按整数分累计并保留两位小数，总热量按每份热量乘份数累计。水煮蛋、西兰花、米饭和鸡胸肉各一份合计6元、408千卡。当前选择仅保存在本页，刷新或离开后清空。单点也参与原有自动热量推荐。示例热量按所列份量估算，实际数值随食材、份量和烹饪方式变化。

原资料未提供分类、口味及照片。分类按菜名初分并标记为待核实，口味统一为“待核实”，图片显示统一占位。管理员确认实际情况后，可修改分类、口味并勾选“分类和口味已核实”，上传对应图片。

窗口采集评分独立保存，不参与菜品平均分。菜品评价初始为空，平均分由学生实际评分计算并保留一位小数。同一学生对同一菜品只有一条评价，再次提交更新原记录，分数为1～5的整数，留言最多200字。价格筛选包含上下限，支持只填最低或最高金额，金额最多两位小数。

## 开发运行

后端在 `backend` 目录执行：

```powershell
mvn spring-boot:run
```

前端在 `frontend` 目录执行：

```powershell
npm ci
npm run dev
```

前端开发地址为 `http://127.0.0.1:5173`，将 `/api`、`/uploads` 代理到后端8080端口。数据库连接凭据通过环境变量提供，MySQL数据库须先创建。

## 配置与持久化

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `8080` | 后端端口 |
| `DB_URL` | 本机3306的 `campus_canteen` | JDBC连接 |
| `DB_USER` | `root` | 数据库账号 |
| `DB_PASSWORD` | 无 | 数据库密码 |
| `UPLOAD_DIR` | `backend/uploads` | 从backend目录启动时的图片目录 |
| `ADMIN_USERNAME` | `admin` | 首次管理员账号 |
| `ADMIN_PASSWORD` | 自动生成 | 首次管理员密码 |

用户、菜品、窗口与评价保存在MySQL，图片存储在上传目录。迁移时同时保留数据库和图片目录，保持图片引用可访问。现有实验报告及需求文档未纳入构建过程。

## 主要接口

响应格式为 `code`、`message`、`data`，成功时 `code=0`。分页数据的 `data` 包含 `items`、`total`、`page` 和 `pageSize`。写入请求发送 `X-Requested-With: XMLHttpRequest`，身份由服务端会话读取。

| 方法与路径 | 功能 | 权限 |
| --- | --- | --- |
| `POST /api/auth/register` | 创建学生账号 | 访客 |
| `POST /api/auth/login` | 登录 | 访客 |
| `POST /api/auth/logout` | 退出 | 当前会话 |
| `GET /api/auth/me` | 当前身份 | 所有人 |
| `GET /api/metadata` | 食堂、窗口及标签 | 所有人 |
| `GET /api/dishes` | 菜品筛选与分页 | 所有人 |
| `GET /api/dishes/random` | 当前条件随机抽取 | 所有人 |
| `GET /api/dishes/{id}` | 菜品详情与留言 | 所有人 |
| `GET /api/nutrition/recommendations` | 按目标热量calories和可选食材ingredient推荐组合 | 所有人 |
| `GET /api/nutrition/single-items` | 查询有完整营养资料的有效单点食材 | 所有人 |
| `PUT /api/dishes/{id}/review` | 新增或更新本人评价 | 学生 |
| `GET /api/admin/statistics` | 资料统计 | 管理员 |
| `POST/PUT/DELETE /api/admin/canteens[/{id}]` | 食堂维护 | 管理员 |
| `POST/PUT/DELETE /api/admin/stalls[/{id}]` | 窗口维护 | 管理员 |
| `POST/PUT/DELETE /api/admin/dishes[/{id}]` | 菜品维护 | 管理员 |
| `POST /api/admin/images` | 图片上传 | 管理员 |
